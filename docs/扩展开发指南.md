# 扩展开发指南

本文给出常见二次开发场景的**具体改法**。所有片段都基于当前源码，可直接复制后微调。
通用原则：**保持零第三方依赖**；改动后跑对应测试；用户可见的变化同步更新 `使用说明.md`。

---

## 1. 新增一个分发平台

两种方式，选一种即可。

**A. 只给当前这套部署加平台（推荐，零代码）**
界面「设置 → 分发平台 → 新增」，填平台名、账号类型、发布形态、风格、篇幅、结构、受众。
数据落在 `platforms` 表，随数据库一起备份。

**B. 让新环境默认就带这个平台（改种子）**
在 `app/seeds.py` 的 `PLATFORMS` 列表里追加一项，字段与现有条目一致：

```python
{
    "name": "小红书",
    "account_type": "personal",          # official / personal
    "formats": ["图文"],                  # 多形态时同平台多篇会自动轮换
    "style": "第一人称体验分享，口语化，多用短句和具体场景；不用行业黑话。",
    "length_hint": "400-800 字",
    "structure_hint": "场景切入 → 3 个具体感受 → 适合谁/不适合谁 → 一句话结论",
    "audience": "25-35 岁女性为主，看重真实体验与性价比",
},
```

注意：
- `seeds` 只在**空库首次启动**时写入，已有库不会自动补。需要给存量库补平台，写一次性迁移或让用户在界面里加。
- `prompts.layout_for()` 里按平台名给了「小标题结构模板」。新平台没有匹配项会走默认模板（`_default`），能正常出稿；想让结构更贴合，在 `layout_for` 里加一个分支。
- 加完跑 `python tools/test_crud.py` 与 `python tools/test_copy.py`。

## 2. 新增资料解析格式

`app/parsers.py` 已经预留注册入口：

```python
# app/parsers.py

def parse_rtf(data):
    text = _decode(data)                 # 复用现有解码逻辑
    text = re.sub(r"\\[a-z]+-?\d* ?", " ", text)   # 粗处理控制字
    return _cap(_clean(text))


register(".rtf", "RTF 文档", parse_rtf)  # 放在文件末尾、PARSERS 定义之后
```

约定：
- 解析函数签名 `fn(data: bytes) -> str`，返回**纯文本**（表格转成 `A | B` 行、PPT 按页分段）。
- 必须复用 `_clean()` 清空白、`_cap()` 截断（单份 20 万字上限），不要绕开。
- 明确不支持的格式放进 `KNOWN_UNSUPPORTED`，写一句「用户能照做的替代方案」，比报「不支持」有用得多。
- 前端不用改：`/api/parse` 会把 `supported_hint()` 返回给界面显示。
- 加测试：在 `tools/test_parsers.py` 里造一个小样本，断言字数与关键字。

## 3. 新增写作角度 / 平台结构

**写作角度**在 `app/seeds.py` 的 `ANGLES`：

```python
{
    "name": "避坑型",
    "brief": "先列出 3-5 个常见误区，每个误区讲清「错在哪、后果是什么、正确做法是什么」，最后给一份自查清单。",
    "intent": "用户已经踩过坑或怕踩坑",
},
```

`generator` 会按「同一平台不连续用同一个角度」轮换，并在 `prompts` 里把 `brief` 注入。
新增后建议同步 `app/prompts.py` 的 `SUB_ANGLES`（切口池）保持风格一致。

**平台结构模板**在 `prompts.layout_for(platform, fmt)`，返回小标题列表。例如：

```python
if "小红书" in name:
    return ["先说结论", "我的实际用法", "这几个细节最影响体验", "适合谁"]
```

## 4. 接到公司服务器（上传落库）

已实现标准 POST，只需在界面「设置 → 上传与存储」选「推送到服务器接口」，填地址与令牌。
服务端要求：接收 `POST` 的 JSON（整套方案，含稿件、资料全文、关键词、偏好表与风险清单快照），**返回 2xx 即视为成功**。

要改鉴权方式或返回结构，改 `app/store.py` 的 `HttpUploadAdapter.push()`：

```python
class HttpUploadAdapter:
    name = "http"

    def push(self, plan, settings):
        url = settings.get("upload_url") or ""
        if not url:
            raise RuntimeError("未配置上传接口地址")
        body = json.dumps({"payload": plan, "source": "geo-workbench"},
                          ensure_ascii=False).encode("utf-8")
        req = urllib.request.Request(url, data=body, method="POST")
        req.add_header("Content-Type", "application/json; charset=utf-8")
        req.add_header("X-Api-Token", settings.get("upload_token") or "")   # 改成公司约定的头
        with urllib.request.urlopen(req, timeout=60) as resp:
            text = resp.read().decode("utf-8", "ignore")
        return f"HTTP {resp.status} {text[:300]}"
```

新增第三种模式（如 S3 / OSS）时：写一个带 `name` 和 `push(plan, settings)` 的类，
在 `get_upload_adapter()` 里按 `settings["upload_mode"]` 分发，界面下拉框加一个 option 即可。

## 5. 换数据库（MySQL / PostgreSQL）

`Store` 对上层只暴露方法，所有 SQL 都集中在 `app/store.py`。替换步骤：

1. 把 `conn()` 换成返回对应驱动的连接（需引入第三方库，属**例外情况**，需团队评审）。
2. 建表语句 `CREATE TABLE` 改成目标方言；`AUTOINCREMENT` → `AUTO_INCREMENT` / `SERIAL`。
3. `?` 占位符改成 `%s`；`PRAGMA table_info` 换成 `information_schema.columns`。
4. `_seed_if_empty()` / `_recover_interrupted()` 逻辑保留不动。
5. 注意 SQLite 的 JSON 字段目前是 TEXT 存字符串，换库后可保留 TEXT（改动最小），不要急着上 JSONB。

> 单机交付场景不建议换库。只有在「多人同时在线、集中部署」时才值得付这个成本。

## 6. 内网部署，同事用 IP 访问

`app/server.py` 的 `main()`：

```python
httpd = ThreadingHTTPServer(("0.0.0.0", port + i), Handler)   # 原为 127.0.0.1
```

同时把控制台打印和 `_running_instance()` 里的 `127.0.0.1` 一并换成实际 IP 或保留本机探测。
**风险提示**：服务没有登录鉴权，任何能访问该端口的人都能读写全部方案与设置（含 API Key）。
要上内网必须先加一层访问控制（反向代理 Basic Auth 或网关鉴权），否则不要把端口暴露出去。

## 7. 加一个新接口（标准三件套）

以「按平台统计字数」为例。

**① 后端** `app/server.py` — `route_get` 里加分支（写操作加到 `route_write`）：

```python
if p.startswith("/api/plans/") and len(parts) >= 4 and parts[3] == "stats":
    plan = STORE.get_plan(int(parts[2]))
    if not plan:
        return self._err("方案不存在", 404)
    stat = {}
    for a in STORE.list_articles(plan["id"]):
        stat[a["platform_name"]] = stat.get(a["platform_name"], 0) + len(a["body_md"])
    return self._json({"ok": True, "stats": stat})
```

**② 前端** `web/app.js` — 用统一的 `api()` 封装：

```js
const r = await api(`/api/plans/${S.plan.id}/stats`);
if (r.ok) renderStats(r.stats);
```

**③ 测试** `tools/test_stats.py` — 建临时库（`GEO_DB` 指向 tmp）、造方案与稿件、起 `/api/...` 或直接调 `Store` 断言。
沿用现有脚本的 `ok(name, cond)` 计数风格，末尾打印 `PASS n / FAIL m` 并以退出码表达结果。

**④ 顺手**：新接口若涉及 `api_key`，返回前必须过 `mask_settings()`；错误用 `self._err("中文提示")`，别抛英文异常给用户。

## 8. 提示词改动的注意事项

`app/prompts.py` 是出稿质量的核心，改动成本最高、回归面最大：

- `build_system()` 决定「不能写什么」（风险红线、竞品名、导流话术）——**改这里等于改合规底线**，必须评审。
- `build_user()` 决定「这一篇写什么」（资料注入、角度、已用标题/FAQ 去重）——可迭代空间大。
- `build_audit()` 是事实核查提示词，改完跑 `tools/test_audit.py`。
- 资料注入有预算：总 16000 字、单份 6000 字，`_pick_relevant()` 会优先保留与关键词相关的段落。放宽预算会显著增加 token 成本。
- 改完至少跑：`test_copy.py`（写法与竞品规避）、`test_audit.py`（核查）、`test_intake.py`（全流程）。
